Section 06

Architecture direction

  • Command Center = default GUI route of predefined sections; reads through context; never touches vault files. Generated HTML stays read-only/zero-JS.
  • New derived records (never in the vault): profile layout document; section result (with empty/stale/unavailable/error distinction); priority recommendation (citations + policy provenance); override (kind, basis, expiry, status).
  • Write path: safety.derived/safety.commit; backup + SHA + rollback; never a parallel writer.
  • Hybrid reasoning: deterministic baseline is the floor; cloud is an optional reranker behind the privacy gate + budget meter; failures fall back locally.
Section 07

AI & prioritization contract

  • Candidate query — deterministic eligibility (ownership, status, evidence, deadlines, blockers, relationships, permissions).
  • Baseline ranker — transparent factors + fixed safety policies + stable fallback; ships without a model.
  • Context prep — bounded candidates, source-backed evidence, revision fingerprints, data minimization.
  • Privacy gate — classify each field; deny restricted categories; cloud opt-in only.
  • Provider-neutral reasoner — structured schema, timeouts, cancellation, retries, model metadata; no write access.
  • Validator — IDs/evidence refs must exist and be authorized; enforce override precedence; reject hallucinated dates/assignments; distinguish discussed vs committed/explicit.
  • Cache — keyed by profile + source revisions + candidate set + policy/override revision + privacy mode + provider config; invalidate only material deps.
  • Budget meter — real usage; request + monthly limits; warn/suspend at cap; local fallback.
  • Evaluation — privacy-safe scenarios: conflicting deadlines, blockers, competing commitments, stale data, speaker ambiguity, duplicate imports, unsupported claims.

Delivery protocol (single orchestrator)

  • One orchestrator owns scope, ledger, briefs, gates, review, integration; runs integration tests; maintains NEXT-SESSION.md + decision log.
  • Repo flow: ask-matt → grill-with-docs → to-spec → to-tickets → implement; one ticket per commit; full suite + ruff + pre-commit before committing.
