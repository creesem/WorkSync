# Spec — V2 generated HTML interface layer

Status: ready-for-agent

## Problem Statement

The only human-facing surface over canonical work data is the browser GUI, which lives
outside Obsidian. A manager who works inside the vault cannot read projects, the team,
the workday plan, or attention without leaving the vault or opening the GUI, and the
platform's structured entities are not presented anywhere the vault already renders.
HTML Reader can display stored `.html` inside the vault, which would put that surface
where the work already is. The risk is that an HTML layer becomes a second parser and a
second write path: re-reading YAML in JavaScript, or writing canonical content through
Obsidian's `app.vault.modify()`, would break the one-reader rule and the single mutation
gateway that the whole platform depends on.

The interface must therefore be generated by Python from the same structured entities
the platform already produces, written as reproducible derived artifacts into a reserved
vault system folder, read-only and form-free, and navigable back to the canonical notes
through a link form proven to work in HTML Reader.

## Solution

A new `html` subsystem that renders deterministic, static, self-contained `.html` pages
from already-resolved work entities and writes them, as one derived transaction, into
`0. System/Interface/` — a new `generated` derived zone in the mutation contract. The
surfaces are a home index, Today/Workday, Projects, project detail, Team, and person
detail. Python is the only generator and the only reader of frontmatter; the pages carry
no JavaScript and no forms, so HTML Reader's safe mode renders them. Every internal link
uses `obsidian://open?vault=<vault>&file=<vault-relative path>` (`obsidian://` with the
`.html` extension for generated targets), the form proven by the G4 prototype; external
links are plain absolute URLs. Generation is orchestrated by a new
`worksync interface build` CLI command that reads through `work`/`context` and passes
plain structured data into a pure `html` renderer, so `html` never imports `context`.
Existing Markdown views and the browser GUI are left in place.

## User Stories

1. As a manager, I want to open a WorkSync interface inside Obsidian, so that I can read my work without leaving the vault.
2. As a manager, I want one home page that links to every other surface, so that I can navigate the interface.
3. As a manager, I want a Today/Workday page showing my five-slot plan, so that I can see today's committed work.
4. As a manager, I want the Today page to show attention items and waiting work, so that I can act on what matters.
5. As a manager, I want a Projects page listing active projects with status, priority, owner, and health, so that I can survey delivery.
6. As a manager, I want a project detail page, so that I can see one project's people, tickets, actions, meetings, and blockers.
7. As a manager, I want a Team page showing per-person workload, so that I can judge capacity.
8. As a manager, I want a person detail page, so that I can see one person's assignments, follow-ups, and blockers.
9. As a manager, I want every generated page to link back to the canonical note it describes, so that I can jump to the source.
10. As a manager, I want generated pages to link to each other, so that I can navigate the interface.
11. As a manager, I want external links to open in my browser, so that I can follow references.
12. As a maintainer, I want navigation to use the proven `obsidian://` link contract, so that links work on a normal click in HTML Reader.
13. As a maintainer, I want the generator to be pure and deterministic, so that the same inputs produce byte-identical output.
14. As a maintainer, I want every generated page to carry a visible "generated / do not edit" marker, so that no one hand-edits it.
15. As a maintainer, I want every generated page to record its generator, reference date, and sources, so that I can tell what produced it.
16. As a maintainer, I want generated HTML treated as derived state, so that it needs no canonical backup.
17. As a maintainer, I want overwriting an existing generated page to require explicit force, so that an accidental clobber fails closed.
18. As a maintainer, I want generated writes to pass through `safety.commit`, so that containment and write-class policy are enforced in one place.
19. As a maintainer, I want a failed build to leave no partial page set, so that the interface never becomes half-written.
20. As a maintainer, I want generated `.html` never scanned or indexed as a work entity, so that presentation state cannot pollute the domain model.
21. As a maintainer, I want `.html` excluded by extension at the single scanner, so that no second parser is introduced.
22. As a maintainer, I want the `html` package to import no `context`, so that the layer boundary holds and the interface can be split out later.
23. As a maintainer, I want the layer matrix updated, so that the new package and its edges are enforced structurally.
24. As a manager, I want a CLI command to build the interface, so that regeneration is scriptable and reviewable.
25. As a manager, I want a dry run, so that I can see exactly what would be written before anything is.
26. As a manager, I want JSON output, so that scripts and tests consume the same result.
27. As a manager, I want the existing Markdown views kept, so that nothing breaks during the transition.
28. As a manager, I want the browser GUI kept available, so that I retain fallback and non-Obsidian access.
29. As a maintainer, I want the generated zone documented in the mutation contract, so that its policy is explicit and not implicit.
30. As a maintainer, I want the generated folder confirmed by a vault audit, so that it does not collide with existing content.
31. As a maintainer, I want all dynamic text HTML-escaped, so that note content cannot inject markup or script.
32. As a maintainer, I want no JavaScript and no forms in generated pages, so that HTML Reader's safe mode works and no state can persist in the artifact.
33. As a maintainer, I want the build to fail closed when a target cannot be resolved, so that a broken interface is loud, not silent.
34. As a maintainer, I want stale references (deleted or renamed notes) omitted from pages, so that the interface never links to a missing target.
35. As a maintainer, I want a regression test per repaired failure mode, so that each safety property stays true.

## Implementation Decisions

- **New `html` package.** `src/worksync/html/` with three modules: `html.links` (the link
  contract), `html.generator` (pure rendering), and `html.writer` (the contained derived
  write). It depends on `core`, `safety`, and `work` only, and imports no `context`. The
  CLI is the only place that reads `context`.
- **Pure renderer receives data.** The generator takes already-resolved structured input
  (work entity lists, the workday plan, attention items, and any context-derived evidence
  summaries passed as plain values) plus the vault name, `today`, and `generated_at`, and
  returns `GeneratedPage(name, filename, content, sources)` objects. It performs no I/O
  and resolves no vault paths. The CLI builds the input from `work`/`context` and passes
  it in.
- **Link contract (from the G4 prototype).** One helper emits internal links as
  `obsidian://open?vault=<vault>&file=<url-encoded vault-relative path>`. The `.html`
  extension is required for generated targets; the extension is optional only for
  Markdown notes (prototype result). Relative `<a href>` is never used. External links
  are plain absolute URLs. Every value that becomes an attribute or text node is
  HTML-escaped.
- **Surfaces and filenames.** A home `index.html`; `today.html` (five-slot workday plan
  plus attention/waiting); `projects.html` and `project/<safe-name>.html`; `team.html`
  and `person/<safe-name>.html`. Filenames use the existing `core.names.safe_name` helper
  and a deterministic order. Canonical notes are linked, not copied: entity detail pages
  show structured fields plus links to the source note, never the note body.
- **Determinism and provenance.** For fixed inputs, `today`, and `generated_at` the bytes
  are identical. Every page carries a visible "generated / do not edit" marker and an
  HTML-comment provenance block (generator name, reference date, `generated_at`, source
  paths/hashes). No external CSS/JS/asset files; a single inline `<style>` keeps each page
  self-contained and the write set closed.
- **Form-free and script-free.** Pages contain no `<script>`, no forms, and no control
  whose state would be persisted into the artifact (HTML Reader §G1/G5).
- **New `generated` derived zone.** `safety.zones.write_zones` gains
  `"generated": <vault>/0. System/Interface` (reserved path constant owned by `core`),
  and `safety.models.DERIVED_ZONES` gains `"generated"`. The folder is confirmed by the
  vault audit (no existing generated namespace; `0. System` is the system folder). It is
  a derived zone *inside* the vault: containment is checked against both the generated
  root and the vault root, and only `.html` is written there.
- **Derived write policy.** `html.writer` builds one `ChangeSet` of `create`/`update`
  `FileOp`s and calls `safety.commit` once. Creation is allowed; replacing an existing
  generated artifact requires explicit confirmation and `force`, mirroring
  `work.views.write_views`. No canonical backup, reviewer, or reason is required, because
  the zone is derived. A mid-transaction failure rolls back and raises; there is no
  partial page set.
- **Never scanned or indexed.** `inventory.parse.iter_markdown` walks only `*.md`, so
  `.html` is already outside the scanner; the spec adds a regression test proving the
  generated folder contributes no notes, no FTS rows, and no work entities.
- **Fail closed on unresolved targets.** If the source set cannot be produced (a missing
  vault/root, an unreadable note, an ambiguous identity), the build raises before any
  write. Individual stale references (a deleted note) are omitted from a page rather than
  rendered as broken links.
- **CLI.** `worksync interface build` renders and writes the page set, defaulting the
  output root to the configured vault's `0. System/Interface`. It supports `--today`,
  `--generated-at`, `--confirm`, `--force`, `--dry-run` (writes nothing), `--json`, and
  the existing `--vault`/`--runtime` overrides. It mirrors the `worksync views`
  command shape. No HTTP endpoint is added.
- **Existing surfaces unchanged.** `work.views` (Markdown views) and the browser GUI are
  not modified; the generated HTML layer is additive.
- **Documentation.** `docs/architecture.md` gains the `html` layer and its edges;
  `docs/mutation-contract.md` documents the `generated` zone (derived, force-gated
  overwrite, no canonical backup, visible marker, deterministic, never indexed);
  `tests/test_read_only_boundary.py` gains `"html"` to the layer matrix and `"cli"` gains
  the `html` edge.

## Testing Decisions

Good tests exercise external behavior at module and CLI seams, not internals. For a
generated write they assert the complete outcome: destination content, the "generated"
marker, determinism, force gating, rollback, and no canonical side effects.

- **Pure generator seam (`html.generator`).** Same input + `today` + `generated_at`
  yields identical bytes; every page carries the marker and provenance; dynamic text is
  HTML-escaped; internal links use the `obsidian://` contract with the `.html` extension;
  external links are absolute; stale references are omitted; no `<script>` or form is
  emitted; smart/zero-project and zero-person inputs render without error.
- **Link contract seam (`html.links`).** Markdown targets and `.html` targets produce the
  expected encoded `obsidian://open` URLs; vault-relative paths with spaces are encoded;
  external URLs pass through; attribute/text escaping is correct.
- **Writer seam (`html.writer`).** Against a temp vault and the real gateway: the page
  set is written into `0. System/Interface`; an existing page without `force` fails
  closed; a mid-transaction failure restores the prior state and leaves no partial set;
  no canonical note is touched; a root inside the vault but outside the generated folder
  is refused.
- **Boundary/regression.** The full read surface and the generated folder produce no
  vault writes; `inventory` indexes zero generated `.html`; the layer matrix proves
  `html` imports no `context` and the direction is acyclic.
- **CLI seam (`worksync interface build`).** End to end on a fixture vault: `--dry-run`
  writes nothing; a build writes the expected files and prints a summary; `--json`
  returns the same payload; re-running without `--force` fails closed on existing pages.
- **Prior art.** `tests/test_work_views.py` (pure render + contained derived writer),
  `tests/test_safety_gateway.py` (preconditions, backups, rollback),
  `tests/test_cli_views.py` (render/write CLI pattern),
  `tests/test_read_only_boundary.py` (layer matrix), and the prototype verdict at
  `prototype/html-links/README.md` (branch `prototype/html-links`, commit `165ece3`).

## Out of Scope

- Interactive editing, form state, and any canonical write from the HTML layer.
- HTTP endpoints and any transport layer; canonical edits stay on the CLI/GUI.
- Re-parsing YAML/Markdown in JavaScript, or any second reader.
- Removing or freezing the Markdown views and the browser GUI (the GUI is left available).
- New domain semantics or changes to attention/rollup logic; the generator presents
  existing entities.
- Search over generated HTML; `.html` is presentation only.
- Migrations and real-vault parity work.
- Configurable generated location beyond the confirmed `0. System/Interface` reserved path.
- Ticket/decision detail pages and any surface beyond home, Today/Workday, Projects,
  project detail, Team, person detail.
