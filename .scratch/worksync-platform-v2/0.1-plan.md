# Plan — WorkSync 0.1 daily driver (write path + ingest)

Status: approved-in-principle; pending spec/ticket breakdown.

## Objective

A single-user 0.1 daily driver where the user **reads in Obsidian** (generated HTML,
zero-JS) and **does all capture/triage/hygiene/lifecycle work in one browser GUI**, with
a **revamped triage that needs one confirmation, not per-item clicks**.

## Locked decisions

- **GUI write mode is the interactive write surface**; generated HTML stays read-only
  (no JavaScript, no forms). Browser GUI is the interactive write client.
- 0.1 covers all four daily workflows: inbox/rough-note triage, Krisp meetings,
  duplicates/clarification cleanup, and project lifecycle.
- Triage = auto-discover + auto-enrich, then **one batch confirmation**; never auto-write
  on a confidence threshold alone.
- Krisp proposals feed the **same unified batch** as inbox and rough notes.

## Item 2 — GUI write mode architecture

- New `POST /api/action/<name>` seam in `gui`: thin controller → existing
  `work`/`ingest` services → `safety.commit`. No domain logic in JavaScript.
- The server pins the current reviewer (`work.reviewer`); destructive or ownership-changing
  verbs require confirmation plus a human-readable reason.
- Every response returns the change set and the equivalent CLI command.
- First-class **batch confirm**: one GUI action submits a batch change set that either
  commits coherently or rolls back.
- Guardrails unchanged: one scanner, one write seam, SHA preconditions, backups,
  reverse-order rollback, fail closed.

## Item 3 — revamped unified triage + ingest

- **New `ingest` package** (deps `core`/`inventory`/`safety`/`work`), one pipeline per
  concern, each = discover (runtime/derived) → review candidates → gated batch apply.
- **Proposal model (the revamp's core):** a stale-safe manifest of heterogeneous
  candidates — `action`, `project`, `meeting`, `link-existing`, `merge`, `drop`,
  `clarification` — each with proposed fields, confidence, provenance, source path +
  hash, and target. Re-scan retires stale proposals; first-create races are guarded.
- **Zero-interaction discovery/enrichment:** single scanner + deterministic rules first,
  optional local model for owner/project/priority/due/type/duplicate — suggestions only,
  never authoritative.
- **One review screen:** all rows pre-filled and pre-selected; inline override only for
  exceptions; drop/merge carry an editable default reason; **one Apply** →
  multi-file `safety.commit` (create active notes, relocate/drop inbox source only after
  the destination is verified and a backup exists; move, never silent delete).
- **Krisp** produces meeting-note candidates into the same manifest; **duplicates /
  clarification cleanup** and **project lifecycle** (issue, report-acceptance, date-gap,
  waiting) reuse the same review→commit pattern.

## Invariants and guardrails

- Review-first: no auto-write on confidence; one human confirm per batch; named reviewer
  and reason on destructive or ownership-changing changes.
- Multi-file operations complete coherently or restore; never remove an inbox source
  before the destination write succeeds and a backup exists.
- Stale/hash/ambiguous/OneDrive-moved targets fail closed; sidecars validated against the
  exact file.
- Generated HTML never scanned or indexed; no second YAML/Markdown parser.

## Risks / open items

- **Batch transaction granularity:** one `ChangeSet` for the whole batch vs grouped
  commits with stop-on-failure — settle in Spec 5.
- **Local-model dependency:** Ollama `qwen3:1.7b` for enrichment; deterministic fallback
  mandatory.
- **Krisp external dependency:** API and `config/secrets.json` do not exist in the new
  repo yet; OneDrive-safe sidecar handling.
- **GUI reviewer workflow:** how the current reviewer is set/rotated in the GUI.
- **Runtime migration:** migrate human decisions/backups/unpromoted source; regenerate
  index; discard logs.

## Deferred (not in 0.1)

- Email intake and prepared communications.
- Task workbench and local-AI workbench.
